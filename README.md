
# Beyond ML: Theory & Practice

**Understand the theory. Explore the mathematics. Master the practice.**

Beyond ML is a local Retrieval-Augmented Generation (RAG) application designed to explore the mathematical, statistical, and computational foundations of Machine Learning and Deep Learning.

The system uses four scientific textbooks as its knowledge base. Users can ask technical questions, retrieve relevant passages, and receive context-based explanations generated by a locally hosted language model.

---

## 1. Project Overview

Understanding Machine Learning requires more than knowing how to use algorithms. It requires understanding the mathematical principles, statistical assumptions, and computational mechanisms behind them.

Beyond ML aims to provide an interactive learning environment where users can explore these foundations through a collection of scientific textbooks.

The application combines semantic search with local language model generation to provide answers grounded in retrieved textbook passages.

### Knowledge Base

The system currently uses four textbooks:

1. Christopher M. Bishop — *Pattern Recognition and Machine Learning*
2. Ian Goodfellow, Yoshua Bengio, and Aaron Courville — *Deep Learning*
3. Aurélien Géron — *Hands-On Machine Learning with Scikit-Learn, Keras, and TensorFlow*
4. Kevin P. Murphy — *Machine Learning: A Probabilistic Perspective*

---

## 2. Key Features

- **PDF processing:** Extracts text page by page from scientific textbooks.
- **Page-aware chunking:** Splits extracted text into overlapping chunks while preserving source metadata.
- **Semantic embeddings:** Converts text passages into dense vector representations.
- **Vector search:** Retrieves relevant passages using FAISS and cosine similarity.
- **Local LLM generation:** Generates answers using Qwen 2.5 1.5B through Ollama.
- **Source inspection:** Displays retrieved passages, book titles, PDF page numbers, and similarity scores.
- **Interactive interface:** Provides a conversational learning experience through Streamlit.
- **Local execution:** Runs the retrieval and generation pipeline locally.

## 3. System Architecture

The application follows a standard Retrieval-Augmented Generation architecture.

```text
                 SCIENTIFIC TEXTBOOKS
                    (PDF documents)
                           |
                           v
                   PDF TEXT EXTRACTION
                       (PyMuPDF)
                           |
                           v
                    TEXT CHUNKING
                 (Page-aware, overlapping)
                           |
                           v
                    TEXT EMBEDDINGS
                (multilingual-e5-small)
                           |
                           v
                     FAISS INDEX
                           |
                           |
USER QUESTION ------------+
       |
       v
QUERY EMBEDDING
       |
       v
SEMANTIC RETRIEVAL
       |
       v
TOP-K RELEVANT PASSAGES
       |
       v
CONTEXT + USER QUESTION
       |
       v
LOCAL LANGUAGE MODEL
             (Qwen 2.5 1.5B)
       |
       v
GENERATED ANSWER
       |
       v
STREAMLIT INTERFACE
```

### Main Components

| Component | Technology | Responsibility |
|---|---|---|
| PDF extraction | PyMuPDF | Extracts text and page metadata |
| Chunking | Python | Creates overlapping text segments |
| Embeddings | Sentence Transformers | Encodes passages into vectors |
| Vector database | FAISS | Performs similarity search |
| Language model | Qwen 2.5 1.5B | Generates contextual answers |
| LLM runtime | Ollama | Runs the model locally |
| User interface | Streamlit | Provides the interactive application |

## 6. Installation and Setup

### Prerequisites

- Python 3.10 or later
- Git
- Ollama
- The four textbook PDF files

### Step 1: Clone the repository

```bash
git clone <https://github.com/Abderrahmane-mega/beyond-m.git>
cd Beyond-ML
```

### Step 2: Create a virtual environment

On Windows:

```bash
python -m venv .venv
.venv\Scripts\activate
```

### Step 3: Install dependencies

```bash
pip install -r requirements.txt
```

### Step 4: Install and configure Ollama

Install Ollama from:

https://ollama.com/

Download the language model:

```bash
ollama pull qwen2.5:1.5b
```

Make sure Ollama is running before launching the application.

### Step 5: Add the textbooks

Place the four PDF files inside the `books/` directory.

The original textbooks are not included in this repository.

## 7. Building the Knowledge Base

The knowledge base is generated through three main stages.

### Stage 1: PDF extraction

```bash
python -m src.pdf_extractor
```

Extracts text page by page and stores the results in:

`data/processed/pages.jsonl`

### Stage 2: Text chunking

```bash
python -m src.chunker
```

Splits the extracted pages into overlapping chunks while preserving document metadata.

The current implementation uses a target chunk size of approximately 1,800 characters and an overlap of 250 characters.

Output:

`data/processed/chunks.jsonl`

### Stage 3: Embedding and indexing

```bash
python -m src.build_index
```

Generates dense embeddings using `multilingual-e5-small` and stores them in a FAISS index.

The current knowledge base contains approximately:

- 3,456 extracted pages
- 6,135 text chunks
- 384-dimensional embeddings

The FAISS index uses normalized embeddings and inner-product similarity, equivalent to cosine similarity.

## 8. Running the Application

Once the knowledge base has been built and Ollama is running:

```bash
python -m streamlit run app.py
```

Open the local URL displayed in the terminal, usually:

`http://localhost:8501`

Users can ask questions about topics such as:

- Linear and logistic regression
- Regularization and weight decay
- Bayesian inference
- Kernel methods
- Neural networks
- Optimization algorithms
- Statistical learning theory

The interface also allows users to inspect the passages retrieved by the system.

## 9. Current Limitations

The project is an experimental learning assistant, not a guaranteed source of mathematically verified answers.

Several limitations are important.

### Retrieval limitations

- Retrieval relies on dense vector similarity.
- Semantically related passages are not necessarily the most useful passages for a specific question.
- The current system does not implement hybrid search or reranking.
- Character-based chunking may split mathematical explanations across passages.

### Generation limitations

- Qwen 2.5 1.5B has limited reasoning and mathematical capabilities.
- The model can produce plausible but incorrect explanations.
- Mathematical expressions and derivations may contain errors.
- The model may fail to distinguish closely related statistical concepts.

### Document processing limitations

- PDF text extraction can introduce formatting artifacts.
- Mathematical notation, equations, and diagrams are not always represented correctly in extracted text.
- Page references correspond to PDF page numbers and may differ from printed book page numbers.

### Source grounding

Retrieved passages are displayed to make the answer's context inspectable. However, their presence does not guarantee that every statement in the generated answer is supported by those passages.
